# Inlu 2.0 — редизайн inlu.com (Next.js)

Лендинг Inlu для UX- и веб-дизайнеров и продуктовых команд. Каждая ключевая функция показана интерактивным демо на реальном макете.

Эта версия — копия `inlu-next-js-2.0` с переписанными текстами. Цель — показать ценность командам, которые уже работают в другом дизайн-инструменте, и убедить их перейти в Inlu.

## Что изменилось по сравнению с 2.0

- **Новое главное обещание:** «Design it once. Ship it as code.». Раньше было «Design together. One click to code.». Совместной работой уже никого не удивишь, поэтому в центре теперь шаг, который другие инструменты оставляют разработчикам.
- **Импорт — главное действие.** Основная кнопка на первом и последнем экране — «Import .fig or .sketch», триал стал второй кнопкой. Импорт `.fig` или `.sketch` — самый безопасный первый шаг для команды, которая переходит с другого инструмента.
- **Новый порядок секций.** Секция Import поднята на второе место, сразу после первого экрана: она снимает главный страх переезда («мои файлы сломаются»). Затем идёт экспорт кода — главное отличие Inlu.
- **Новая секция `ToolCompare` («Why switch», `#compare`).** Честная таблица «Other design tools vs Inlu»: сначала то, что есть везде (multiplayer, компоненты, переменные, auto layout), затем то, чем Inlu отличается (код, брейкпоинты, логика прототипа в экспорте, доступ для разработчиков).
- **Конкуренты на сайте не называются.** Вместо названий — «other design tools», «your current tool» и форматы файлов `.fig` / `.sketch`. Если постоянно называть конкурента, Inlu выглядит как дополнение к нему, а сайт рекламирует чужой продукт.
- **ValueStrip показывает выгоды, а не количество функций:** 0 пересобранных экранов, 4 платформы, 1 источник правды для дизайна и кода, 0 спецификаций для передачи разработчикам.
- **DesignSystem и Collaboration показывают, что при переезде ничего не теряется** («Nothing you rely on is missing», «Designers and developers in one file»). Это не новинки, а привычные вещи, которые на месте.
- **PrototypeFlow:** акцент перенесён на то, что логика и переменные прототипа попадают в экспорт и разработчикам не нужно писать их заново.
- **FAQ начинается с вопросов о переезде:** сохранятся ли файлы, можно ли попробовать, не уходя со старого инструмента, сколько времени займёт переход.
- **Прайсинг:** добавлена фраза «One seat covers design, prototyping and code output — no separate developer seats».
- **Намеренно не добавлены:** обещания, которые нечем подтвердить, например «импорт за 5 минут» или «экспорт обратно в старый инструмент».

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
npm run build && npm start   # production-сборка
```

Стек: Next.js 16 (App Router), React 19, TypeScript. Шрифты Onest, Source Sans 3 и JetBrains Mono подключены через `next/font`.

## Структура

```
app/
  layout.tsx        шрифты, метаданные, глобальные стили
  page.tsx          сборка страницы из секций
  styles.css        токены (:root), типографика, навигация, прайсинг, FAQ, модалка
  demos.css         стили всех интерактивных демо
  icon.svg
components/
  sections/*.tsx    по компоненту на секцию: Hero, Import, CodeExport, ToolCompare, Responsive, PrototypeFlow, Pricing…
  PageScripts.tsx   клиентский компонент, запускает интерактив после загрузки
lib/
  interactions.js   логика демо, попап «Talk to us», мелкие детали для дизайнеров
  code-samples.js   экспорт checkout в 4 форматах: дерево файлов + привязка слоёв к строкам кода
  hero-sample.js    подсветка синтаксиса и карточка Booking card для демо на первом экране
```

Секции — серверные компоненты. Страница генерируется статически, поэтому первый экран отдаётся сразу, а поисковики видят весь текст. Вся интерактивность собрана в одном клиентском модуле.

**Порядок секций:** Hero → ValueStrip → Import → CodeExport → ToolCompare → Responsive → PrototypeFlow → DesignSystem → Collaboration → Directions → Pricing → FAQ → Final CTA. Компонент `Testimonials` есть, но на страницу не подключён, пока в нём заглушки.

## Для кого и какая задача

**Основной сегмент** — продуктовые команды из 5–50 человек, где 1–5 дизайнеров работают вместе с веб- или мобильными разработчиками: стартапы и продуктовые компании, которые регулярно выпускают интерфейсы. Пользователь — UX/UI-дизайнер. Решение о покупке принимает дизайн-лид, Head of Design или продакт.

**Дополнительный сегмент** — фрилансеры и небольшие студии, которым нужно быстро отдать клиенту работающую вёрстку, а не только макет.

**Задача пользователя (Job to be Done):**
> Когда макет утверждён и его нужно передать в разработку, я хочу, чтобы он превратился в корректный код без повторной сборки, — чтобы релиз выглядел как макет, а команда не тратила итерации на правки «это не как в дизайне».

**Задача посетителя лендинга:** за пару минут понять, какой код получается на выходе и сколько это стоит, чтобы решить, стоит ли пробовать.

**Главные сомнения при переходе с другого инструмента** (именно на них отвечает эта версия текстов):
1. «Мои файлы сломаются» — секция Import и первый вопрос в FAQ;
2. «Команде придётся переучиваться» — DesignSystem, Collaboration, таблица сравнения, FAQ;
3. «А зачем, если всё и так работает?» — CodeExport и строки таблицы, где Inlu отличается;
4. «Нельзя будет вернуться» — FAQ «Can we try Inlu without leaving our current tool?»: можно перенести один проект, остальное оставить где было.

**Чем пользуются сейчас:**
- Figma + Dev Mode + ручная вёрстка по спецификации;
- плагины экспорта из Figma (Anima, Locofy);
- Framer и Webflow — для сайтов, но без SwiftUI и Flutter.

Во всех случаях либо макет пересобирают вручную, либо код получается только под одну платформу. На этом стыке и находится Inlu.

## Value Proposition

**«Design it once. Ship it as code.»**

Подзаголовок: *Everything you expect from a design tool — plus the step other tools leave to developers.*

Суть: **всё, к чему команда привыкла в своём дизайн-инструменте, плюс утверждённый макет сразу становится рабочим кодом, без передачи разработчикам и ручной пересборки.**

Почему я выбрала именно эту формулировку:

- **Главная боль аудитории — передача макета в разработку.** Макет перерисовывают в коде, и при этом теряются отступы, состояния и брейкпоинты. Каждая итерация — ещё один круг правок.
- **Совместный дизайн есть в любом современном инструменте.** Заголовок «Design together» описывает то, что у человека уже есть, и не даёт повода переходить. Отличает Inlu вывод в React / HTML/CSS / SwiftUI / Flutter, поэтому это отличие стоит в заголовке.
- **Подзаголовок снимает страх потерь:** «everything you expect» — значит, отказываться ни от чего не придётся. «Plus the step…» — значит, вы получаете больше, чем сейчас.
- **Обещание подкреплено демо.** «Ship it as code» звучит как маркетинг, пока не видно, какой код получается. Поэтому рядом с каждым обещанием стоит демо, где результат можно потрогать.

## Продуктовые решения

1. **Показывать, а не рассказывать.** Каждая ключевая функция — интерактивное демо на реальном детализированном макете, без абстрактных плашек:
   - на первом экране наведение на слой подсвечивает его код;
   - экспорт показан с деревом файлов;
   - адаптив и прототипирование разобраны по шагам;
   - есть цепочка «стиль → экраны».
2. **Экспорт — центр страницы.** Реальный экран checkout и структура экспортированного проекта в четырёх форматах. Клик по части макета открывает нужный файл и подсвечивает строки. Это отвечает на главный вопрос скептика: «а какой код он выдаёт?»
3. **Адаптив — пошаговой демонстрацией, без искажения макета.** Фрейм только уменьшается целиком и действительно перестраивается под 1280 / 768 / 390. На последнем шаге остаётся только код медиа-запросов.
4. **Прототипирование — через сравнение.** Один и тот же флоу оформления заказа сделан двумя способами: «прототип как отдельный слой» и Inlu (состояния внутри одного фрейма, переменные, условие). Разница видна в числах: 6 фреймов и 7 связей против 4 фреймов, 3 связей и 1 правила. Главный аргумент — логика прототипа попадает в экспорт, и разработчикам не нужно писать её заново.
5. **«One canvas. Many directions» — весь флоу целиком:** сгенерировать стиль → попросить дашборд в этом стиле → мобильный экран → второе направление, на которое перекрашиваются все экраны.
6. **Прайсинг на главной, с конкретными ценами.** Когда цена неясна, пользователь не начинает. Пока модель тестируется, условия беты обозначены явно: цена фиксируется на 12 месяцев, об изменении лимитов предупреждаем за 30 дней.
7. **7-дневный триал Professional без карты.** Ключевой ценностный момент — первый экспорт кода, а на бесплатном Starter экспорт доступен только как превью. Триал даёт дойти до этого момента без оплаты.
8. **«Talk to us» — попап вместо отдельной страницы.** Пользователь не уходит со страницы с ценами. Для A/B-теста контрольный вариант с отдельной страницей открывается по адресу `?talk=page`.
9. **Стиль и детали для дизайнеров.** Визуальный язык inlu.com: Onest, кнопки-пилюли, первый экран в рамке с градиентом, тёплые градиенты в заголовках. Плюс мелочи, которые дизайнер узнает:
   - клавиша **G** включает сетку;
   - при наведении на заголовок видна его типографика;
   - в углу показываются координаты X/Y;
   - клик по цвету палитры копирует его hex.

   Всё это сигнализирует «сделано дизайнерами для дизайнеров» и делает страницу запоминающейся.
10. **Сначала снимаем страх переезда, потом продаём отличие.** Import стоит сразу после первого экрана, а таблица сравнения — сразу после экспорта. Посетитель сначала видит, что его файлы откроются, потом — что он получит, потом — что ничего не потеряет.
11. **Честное сравнение без имён.** В таблице `ToolCompare` три строки — «одинаково у всех» (они показаны приглушённо), остальные — реальные отличия. Честность в общих пунктах добавляет доверия к пунктам, где Inlu сильнее. Конкуренты не называются: колонка подписана «Other design tools».

## Ключевые метрики

**North Star — число утверждённых фреймов, экспортированных в код за неделю.** Это прямой показатель того, что продукт выполняет главное обещание, а не просто собирает регистрации.

**Сайт (работает ли страница):**
- CTR главных кнопок первого экрана — «Import .fig or .sketch» и «Start 7-day trial»;
- доля посетителей, которые дошли до таблицы сравнения (`#compare`) и перешли по пункту меню «Why switch»;
- запуски демо импорта («Try a sample import»);
- вовлечённость в демо:
  - доля посетителей, которые переключают формат или кликают по слою в экспорте;
  - сколько досматривают адаптив до 5-го шага;
  - сколько запускают Play в прототипе;
- глубина скролла до прайсинга;
- конверсия визит → старт триала, в разрезе тех, кто трогал демо, и тех, кто не трогал;
- «Talk to us»: открытие → отправка формы; попап против страницы в A/B;
- доля выбравших годовую оплату.

**Активация (работает ли продукт):**
- время до первого холста;
- доля триалов с импортом .fig/.sketch в первый день и доля импортов без ошибок;
- **первый экспорт кода в первые 3 дня** — главный aha-момент.

**Удержание и монетизация:**
- конверсия триал → платный план на 7-й день, по когортам с экспортом и без;
- удержание команд на 1-й и 4-й неделе; рост числа редакторов в команде (показатель мультиплеера);
- качество экспорта: какая доля кода попадает в репозиторий без переписывания (через интеграцию с Git или опрос), CSAT по коду;
- причины оттока.

**Ограничители:** скорость загрузки (LCP < 2,5 с на мобильных), процент отказов на первом экране.

## Гипотезы и критерии успеха

Каждое крупное решение на странице — гипотеза, которую нужно проверить. Пороги ниже — стартовые ориентиры, их уточняют по базовым значениям после первых двух недель аналитики.

| # | Гипотеза | Как проверяем | Метрика успеха | Ограничитель |
|---|---|---|---|---|
| 1 | Интерактивное демо экспорта убеждает лучше, чем описание, и повышает конверсию в триал | A/B: интерактивное демо против статичного скриншота с тем же текстом | Конверсия визит → триал: **+15%** относительно контроля | LCP на мобильных не хуже 2,5 с |
| 2 | Цены прямо на главной снижают неопределённость и отказы | A/B: тарифы на главной против кнопки «View plans» с переходом на отдельную страницу | Конверсия визит → триал: **+10%** | Число заявок «Talk to us» не падает |
| 3 | Триал без карты даёт больше стартов, а платящих в итоге становится больше | A/B: триал без карты против триала с картой | **Оплаченные подписки на 100 визитов** ≥ контроль +10% (сравниваем итог, а не только старты) | Конверсия триал → оплата не ниже 8% |
| 4 | Попап «Talk to us» собирает больше заявок, чем отдельная страница, потому что не уводит с прайсинга | A/B: попап против страницы (`?talk=page`) | Заявки на 100 посетителей прайсинга: **+20%** | Доля квалифицированных заявок не падает |
| 5 | Первый экспорт кода — aha-момент: те, кто экспортировал в первые 3 дня, платят заметно чаще | Когортный анализ триалов: с экспортом и без | Конверсия в оплату у когорты с экспортом **≥ 2×** | — |
| 6 | Обещание «Design it once. Ship it as code.» и импорт как главная кнопка приводят больше команд, которые переходят с другого инструмента | A/B первого экрана: новый вариант против прежнего («Design together. One click to code.», главная кнопка — триал) | Импорты в первый день на 100 визитов: **+15%**, конверсия в триал не ниже контроля | Отказы на первом экране не растут |
| 7 | Таблица сравнения снижает сомнения и повышает конверсию у тех, кто до неё дошёл | A/B: страница с секцией `ToolCompare` против страницы без неё | Конверсия визит → импорт/триал: **+10%** | Глубина скролла до прайсинга не падает |

Если гипотеза 5 подтвердится, онбординг триала нужно строить так, чтобы пользователь дошёл до первого экспорта как можно быстрее.

Тесты идут минимум 2 недели, чтобы захватить полный недельный цикл. Если трафика мало для статистической значимости, тесты запускаются последовательно, а не параллельно.

## Следующие шаги и приоритизация

**Шаг 0, блокер для всего остального:** подтвердить плейсхолдеры (список в конце) — цены, лимиты, условия беты и триала, цифры в демо. Без этого страницу нельзя выпускать.

Остальное оценено по RICE. Все значения — экспертные оценки:
- **Reach** — сколько тысяч посетителей в квартал затронет изменение;
- **Impact** — влияние на конверсию: 0,5 — низкое, 1 — среднее, 2 — высокое, 3 — очень высокое;
- **Confidence** — уверенность в оценке;
- **Effort** — трудозатраты в человеко-неделях.

| Инициатива | Reach | Impact | Confidence | Effort | RICE |
|---|---|---|---|---|---|
| Разметить события в демо и воронке (PostHog / Amplitude) — без этого не проверить ни одну гипотезу | 40 | 1 | 100% | 1 | **40** |
| A/B секции сравнения (гипотеза 7) | 25 | 1 | 50% | 0,5 | **25** |
| Социальное доказательство: наполнить готовый блок «Teams shipping with Inlu» реальными отзывами и цифрами кейсов (сейчас там заготовки) | 40 | 2 | 80% | 3 | **21** |
| A/B: триал без карты против триала с картой (гипотеза 3) | 40 | 2 | 50% | 2 | **20** |
| A/B первого экрана (гипотеза 6) | 40 | 1 | 50% | 1 | **20** |
| A/B «Talk to us»: попап против страницы (гипотеза 4) | 4 | 1 | 80% | 0,5 | **6,4** |
| Настоящий экспорт вместо иллюстрации + кнопка «Open in playground» (StackBlitz) | 25 | 3 | 50% | 6 | **6,3** |
| Мобильные версии демо и аудит доступности | 16 | 1 | 80% | 3 | **4,3** |
| SEO-страницы: Pricing, «Switching to Inlu» (гайд по переезду с .fig / .sketch), Use cases, документация по экспорту | 15 | 1 | 50% | 4 | **1,9** |

**План по горизонтам:**
- **Сейчас (1–2 спринта):** шаг 0 → аналитика → социальное доказательство → A/B триала, первого экрана и секции сравнения.
- **Дальше:** A/B «Talk to us», реальный экспорт с playground, мобильные демо.
- **Потом:** SEO-страницы; техническое развитие — переписать демо в React-компоненты с состоянием (сейчас это один клиентский модуль поверх статической разметки), вынести тексты в CMS, добавить локализацию.

**Параллельно — интервью с 5–8 дизайнерами** из основного сегмента. Цель — узнать, понятна ли ценность за 10 секунд и где появляются сомнения. Результаты могут поменять порядок в таблице, поэтому интервью лучше провести до запуска A/B-тестов.

## Риски и как их снижать

| Риск | Чем грозит | Как снижаем |
|---|---|---|
| **Обещание сильнее реальности.** Экспортированный код требует серьёзной доработки | Лендинг поднимает ожидания, а продукт их не оправдывает → отток в триале, негативные отзывы | Показывать на сайте реальный вывод Inlu, а не идеализированный пример. Формулировка «review before release» уже есть в FAQ. Следить за качеством экспорта: доля кода без переписывания, CSAT |

## Допущения (не факты об Inlu)

- **Цены:** Starter $0, Professional $16 за редактора в месяц ($13 при оплате за год), Organization — по договорённости, от 20 редакторов. На inlu.com публичных цен нет.
- **Условия беты и триала:** без карты, отмена до 7-го дня, цена фиксируется на 12 месяцев, об изменениях предупреждаем за 30 дней.
- **Лимиты тарифов, поддержка, SSO/SCIM** — предложение, а не подтверждённые данные.
- **Цифры в демо** (48 фреймов, 126 auto layout, «6 фреймов / 7 связей» и т. п.) — это цифры примера, а не замеры.
- **Экспортированный код** — правдоподобный пример, а не реальный вывод Inlu.
- **Генерация стилей и экранов ассистентом** — концепт; нужно проверить, есть ли такая функция в продукте.
- **Бренд Morrow Audio и товары** (наушники Aero Lite и т. п.) — вымышленный контент для макетов.
